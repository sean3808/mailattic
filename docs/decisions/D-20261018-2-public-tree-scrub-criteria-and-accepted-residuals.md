## Context

公開版的驗收標準是「懂這個產業的人讀完，猜不出是哪家公司、哪些客戶、在做什麼生意」（`#331`）。清理時把真實值換成虛構值，跨模型審查連續三輪都抓到同一種問題：值換掉了，周圍的語意卻沒跟著換。例如一次性救援腳本的常數同時是停止門檻，換值後停止規則失效；換檔後抽查用的關鍵字換成虛構詞，抽查就失去意義；測試的變數名和測試名還留著原值。

原本的候選原則是「操作用的值只要不識別就還原」。三方會談（Claude／Codex／agy）的結論是方向對，但不能當放行規則：一個值可能同時是操作值又是識別值，而且這條原則管不到「換了值卻沒換齊」的那一類。

## Decision

**每個要改的值同時問兩件事**：它要不要對 repo 外的真實環境才會生效（真實檔案、信庫、目錄名、系統紀錄、排程），以及它認不認得出公司、客戶或生意。

| | 認不出 | 認得出 |
|---|---|---|
| **要對真實環境才生效** | 維持原值 | 改成要操作者代入的參數，或移出公開樹（D-20261018-1） |
| **只需跟 repo 內文字一致** | 不動 | 替換，而且同一指涉的所有位置一次換完：變數名、測試名、縮寫、衍生編碼、註解 |

**已接受殘留**（Sean 2026-10-18 裁決，公開版可見，之後的審閱不再當成問題）：

- 量級資訊：單一信箱、年份區間、語料總數與精確筆數、儲存容量
- 排程預設時刻與排程資料夾名稱（安裝腳本實際使用的值）
- 地區（台北時區的日期語意本來就是行為契約）
- 不識別公司的硬體與作業系統名稱
- 改寫後保留的三份公開方式相關決策紀錄

例子換成虛構值時，文字不能再宣稱「實測過」，要改成「實際觀察到的情形，以虛構值舉例」。

## Rejected alternatives

- **把操作值一律還原**：值可能同時識別身分，例如真實的目錄名或專有名詞，一律還原會把識別內容放回去。
- **再開一輪逐項審查**：沒有判準和停止條件，審查每輪都找得到不一致的地方，不會收斂。
- **連量級與作息也藏起來**：救援腳本與重建手冊就沒辦法照原樣執行；這些資訊也認不出公司或客戶。

## Consequences

- 公開前的掃描與內容審閱，判準都指向本檔與已接受殘留清單，不用再翻 `#331` 的討論串。
- 新增測試資料一律用虛構情境，不從真實信件改寫。
- 已接受殘留清單只能由 Sean 增減；審閱發現清單外的項目，照上表處理。
