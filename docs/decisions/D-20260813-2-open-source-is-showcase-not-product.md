## Context

2026-07-29 在 #24 的拍板有三項，第 3 項是「未來可能開源——保留抽離私有資料的能力」，原文寫明兩件事：專案「有機會成為**對外展示的成果專案**（移除私有 database 之後）」，以及「這是**方向性約束，不是現在就要重構**——用於新增程式碼時的取捨判準，不觸發既有程式碼的改寫」。結尾另加一句「現階段不開任何 issue 追蹤此項」。

同一則拍板的第 1、2 項後來都升格成 [D-20260730-1](D-20260730-1-mcp-capability-parity-and-v2-first-sequencing.md)，#24 因此改標 `roadmap`。**第 3 項是唯一沒升格的，也是唯一漂掉的。** 這不是巧合——2026-07-30 那則自己寫下的「應收斂為一條 ADR 而非僅存於 issue comment」，第 3 項正好沒有照做。

漂移在 15 天內完成，路徑清楚可追：

- #151 User Story 18 先把「future open-source user」寫成角色；
- #152 的 Problem Statement 把它升級為「本專案的方向是開源的 MCP server，**供他人匯入自己的信箱**」，並據此開了一張要對四個 PST 讀取候選各跑一次建置與實測的研究票，標 `ready-for-agent`。

「對外展示」與「供他人匯入自己的信箱」不是同一件事，成本差一個量級：前者的讀者讀架構，後者的使用者要把自己的語料搬進來。**沒有任何一則拍板支持過後者。**

而 #152 的事實前提也不成立。它寫「沒有 Outlook 的使用者將無法使用匯入功能——而匯入是整個平台的入口」，但平台已經有一條零平台依賴的匯入路徑：`ingest.py` 的 `resolve_maildir_sources` / `import_maildir_sources` 搭 `parser.py` 的 `MaildirParser`，吃 maildir 內的 `.eml`，是每日 IMAP sync 天天在走的正式路徑。它既不需要 Outlook 也不需要 `readpst`，唯一缺的是 CLI 入口——目前只有 `imap_runtime.py` 呼叫它。

反方向的證據也查過。2026-07-29 的開源現況調查（`#24`）掃過五個查詢族：同類專案**零**，整個 email MCP 領域的 star 天花板只有 83，全部是 live IMAP／Gmail 代理——server 收到呼叫才去連信箱。**伺服器上已經不在的信，它們結構上拿不到。** 只授權 POP、或不保留五年十年前資料的伺服器，這些情境下本機存檔是唯一來源，而那正是本專案唯一講得出口的差異化主張。展示的價值在這個形狀，不在那顆語料本身。

## Decision

**開源的定位是「對外展示的成果專案」。它不承諾第三方能把自己的信箱搬進來。**

三條可操作的推論：

1. **它授權的支出**：資料與程式碼的邊界工作（DB 路徑、self-address、專屬設定外掛化）。**但這筆錢已經有人付了**——[D-20260730-1](D-20260730-1-mcp-capability-parity-and-v2-first-sequencing.md) 第 5 步遠端化，經 2026-07-30 的更正（`#24`）（私有網路兜底對所有遠端客戶端都不成立）之後，「打通階段只掛去識別化的測試 DB」是唯一選項而非備選。展示是搭這個節點的順風車，增量成本接近零。

2. **它不授權的支出**：為假想的第三方使用者付跨平台成本。跨平台工作需要一個**獨立於開源**的理由——例如遠端化的常駐主機不是 Windows。「開源後別人可能沒有 X」本身不構成理由，因為展示的讀者不執行匯入。

3. **「可跑」的門檻定在樣本可跑**：clone 下來要能對一顆去識別化的小樣本 DB 真的查到東西、且 `contact-history` 的方向判定正確。這一級直接由第 1 點的測試 DB 節點交付。低於這一級（只有讀得懂、或只有空庫起得來）撐不起拍板原文「不是拔掉資料就散架」那句話。

`contact_history.py` 把 self-address 凍死成 `{sean3808@mailattic.test}`（`LANGUAGE.md` 的 `self-address` 詞條記為 v1 凍結，理由是「整個 DB 即此單一信箱」）。**這條在去識別化 DB 掛上去的那天就會失準**，不必等到開源——它屬於第 1 點，不屬於第 2 點。

## Rejected alternatives

- **定位為可用產品（第三方能匯入自己的信箱）**：這是 #152 隱含採用的定位。它會拉出一串票——ingest 跨平台、self-address 設定化、時區設定化、非 Windows 的完工證據鏈——其中最後一項最貴（canonical launcher 是 Windows-only，`project-tool-environment.ps1` 走 `kernel32.dll` P/Invoke，四條 pytest route 在非 Windows 全跑不起來）。而目標客群的規模從未被估過：PST 是 Outlook 自己的檔案格式，「手上有 PST 卻沒有 Outlook」是個窄集合；桌面端以 Windows 為主，跨平台匯入的受眾更小。
- **維持現狀（約束只活在 issue comment）**：這正是被證明會失效的那個狀態。它沒有位置能讓引用者對照，於是 15 天內就被升級成一張研究票的唯一理由。
- **完全放棄開源方向**：拍板第 3 項的實質內容——保持資料與程式碼邊界乾淨——本來就是遠端化要付的錢。放棄開源不會退回這筆支出，只會失去它附帶的定位約束。

## Consequences

- **#152 關閉**，理由是事實前提被 maildir 路徑推翻、且唯一的動機定位被本決定否定。`#151` 的 Outlook COM adapter 是刻意的平台取捨，不因本決定改變——它的 adapter 邊界仍然是日後替換的接縫。
- **另開一張小票做 `bes import --maildir`**：接既有的 `import_maildir_sources`，成本是一個子命令。它同時是差異化主張的入口（沒有 IMAP 的人走得進來）與測試 DB 的餵料路徑。
- **`CLAUDE.md` 的「這是什麼」段改寫**：原句「Sean 個人 AI agent 的長期記憶後端」三段裡，承重的是「長期」（差異化主張）與「後端」（「不是什麼」清單的判準來源），而「Sean 個人 AI agent 的」正在過期——消費端已擴到 CoWork（MCP）、Sean 自己經由 `bes`，roadmap 上還有手機／ChatGPT／Notion。改寫把承重的部分移到前面。**那句話不能刪**：負面清單只有在有正面身分時才判得動，這一輪的 `#152` 就是空位被填的實例。
- **展示用的對外文案（README）現在不寫。** 門面在還沒開門的時候寫，只會寫成一份會過期的行銷稿；且 `tests/test_tag_based_release.py` 對 README + CLAUDE.md + `global-install-and-release.md` 三件套有斷言，動它要連著看。
- **去識別化測試 DB 目前刻意沒有名字。** 它同時服務遠端化連通性實測與展示，是 load-bearing 的東西，但形狀還沒定；命名走 Spectra 的 glossary 路徑，等遠端化真的推進時再做，現在命名等於替一個還沒有形狀的東西凍詞。
- **本決定要被反轉，需要的是一個新的使用者事實**（有人真的要匯入自己的信箱），不是一次「順便也支援一下」的判斷。反轉時第 2 點的成本清單已經列在 Rejected alternatives 第一條。

> **2026-10-10 補記**：定位與三條推論不變，但排序被 [D-20261010-1](D-20261010-1-showcase-ships-ahead-of-remoteization-in-a-fresh-repo.md) 取代——展示不再搭遠端化的順風車，改為提前在全新的公開 repo 上線；「README 現在不寫」同時失效。同一天出現的「部門多人共用一顆存檔」被記為方向，判定為尚不構成上一條所說的反轉事實。
