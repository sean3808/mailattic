## Context

[D-20260813-2](D-20260813-2-open-source-is-showcase-not-product.md) 把開源定位成「對外展示的成果專案」，並把它排成搭遠端化的順風車：邊界工作由 [D-20260730-1](D-20260730-1-mcp-capability-parity-and-v2-first-sequencing.md) 第 5 步的去識別化測試 DB 節點付錢，展示的增量成本接近零；對外文案「現在不寫」。

2026-10-10 Sean 提出一個那條決定沒有預設到的事實：**他想要一個線上看得到的作品，而且想盡早上線**。順風車的排序在「展示沒有期限」時成立；一旦想早點上線就不成立——遠端化沒有排定日期，展示掛在它後面等於沒有日期。

同一天對 tracked 檔案做了一次清點：現行樹的測試樣本與範例設定需要去識別化；DB、附件、`.env`、寄件草稿、備份從未進過版控。

## Decision

**展示提前做，不等遠端化。定位不變（展示，不是可用產品），變的只有排序與載體。**

1. **期限與門檻分兩波。** 第一波的門檻是「讀得懂」：程式、文件、決策紀錄公開。第二波補去識別化樣本 DB，達到 D-20260813-2 第 3 點的「樣本可跑」。那條門檻沒有被降低，只是不再擋住第一天上線。

2. **載體是一個全新的公開 repo，舊歷史不帶。** 舊 repo 搬家後凍結成歷史檔案。

3. **公開 repo 成為主場。** 搬家之後日常開發在那邊進行，不維護兩邊同步。這條有一個前置條件：**提交前的自動檢查**，擋掉真實網域與地址。沒有它就不能公開。

4. **去識別是原則，盡可能做到。** 範例與測試只用保留網域和合成資料。專案改名為 **`mailattic`**，含 Python 套件名稱；CLI 指令 `bes` / `bes-mcp` 保留（來源不可考，與原專案名無關）。

5. **不帶過去的東西**：`openspec/` 全部（已凍結、非現行正典、佔 tracked 檔過半）。測試樣本一律用人工編的假資料。

6. **過程也是展示內容，但換一種方式帶。** `docs/decisions/` 清過後整批帶、行為契約與交付流程原樣帶、另寫 2 到 3 篇案例。原始 issue 與 PR 討論串不搬。

7. **授權 MIT。**

8. **多人共用存檔記為方向，不進範圍。** 未來可能想把幾個人的信箱放進同一顆存檔。這寫進對外說明當方向，第一版不做。它**不構成** D-20260813-2 要求的反轉事實：「有人討論過想要」還不是「有人真的要匯入」。

## Rejected alternatives

- **原地清理後把本 repo 轉公開**：舊歷史不適合公開，現行樹清得再乾淨也改變不了。
- **改寫歷史後轉公開**：留得住 issue 與 PR，但 issue 與留言本身也可能引用真實信件，要逐張清，而且漏一處就收不回來。換到的是原始討論串，而過程最濃縮的部分（決策紀錄）本來就帶得過去。
- **私有 repo 維持主場、定期匯出到公開 repo**：每次匯出都要重清一次，同步成本會讓公開那邊停在第一天。主場搬過去之後洩漏風險確實變成每一次提交都有，所以用第 3 點的提交前檢查換掉它。
- **維持原排序，等遠端化**：與「想盡早上線」直接衝突。
- **第一版就做到樣本可跑**：樣本 DB 的形狀還沒定（D-20260813-2 刻意沒替它命名），把它放進第一版會讓上線取決於一件還沒設計的東西。
- **沿用原專案名稱**：與舊歷史的連結被搜尋引擎或備份站收錄後無法撤回。
- **命名**：`backfile`（講到差異化、接得上 `bes`，但兩個獨立意見都指出台灣讀者容易看成備份工具）、`letterbook`（語意最貼往來紀錄，但 GitHub 有 144 星的同名專案）、帶 `-mcp` 的描述型名稱（MCP 只是三個介面之一，且會把專案放回 live 代理那一群）。2026-10-10 查過 GitHub 名稱搜尋、PyPI、npm，`mailattic` 皆無人使用；**商標與網域未查**。
- **反轉 D-20260813-2、把多人共用列入範圍**：系統目前假設整顆 DB 是單一信箱，多人共用要重新定義收發方向與「哪些地址算自己人」，另加權限，不在第一版範圍。

## Consequences

- **D-20260813-2 的定位與三條推論仍然有效**，被取代的只有兩句：「展示是搭這個節點的順風車」與「展示用的對外文案（README）現在不寫」。該檔已補記指向本決定。
- **README 要寫了。** `tests/test_tag_based_release.py` 對 README + `AGENTS.md` + `docs/global-install-and-release.md` 三件套有斷言，改寫時連著看。
- **「10 萬封以內 FTS5 勝過 RAG」在第一版只能寫成設計取捨，不能寫成效能宣稱。** 目前沒有任何實測數字；數字要等樣本 DB 出來才量得到。
- **改名牽動跨專案的全域 `bes` 與 skill**：搬家後要重新發行一次，其他專案的 subagent 才吃得到新套件名稱。改名在搬家的同一步做，不先在舊 repo 改。
- **`AGENTS.md` 的「這是什麼」與「不是」清單要跟著改**：repo 位置、套件名稱、issue tracker 位置都會變。
- **搬家後 issue 開在公開 repo，不貼真實信件內容。** 需要真實信件當證據的除錯，證據留在本機。
- **已知且接受的殘留風險**：(a) 去識別靠人工加工具，不保證零漏網，上線前要有一次獨立掃描且結果經 Sean 看過；(b) 商標與網域未查。
- **建立公開 repo 與按下公開，是本決定裡唯二收不回來的動作**，兩者都要 Sean 當下親自授權，本決定不構成預先授權。
- **本決定要被反轉，需要的是「想盡早上線」這個前提消失**，或去識別被證明做不到可接受的程度。

## 補記（2026-10-13）：第 6 點的案例不放在 repo

第 6 點的「另寫 2 到 3 篇案例」已寫出三篇（門面那一輪），Sean 讀過後決定拿掉：repo 與 README 的讀者是想知道這個專案怎麼用的人，開發過程的故事是另一群讀者要看的，改放在 repo 外，需要時連同 repo 連結一起給。

同一次也定了 README 的寫法：當成使用文件寫，能用與不能用的路徑照實列，不寫「這是展示、不是產品」這類定位宣告。[D-20260813-2](D-20260813-2-open-source-is-showcase-not-product.md) 的實質不變（不為假想使用者付跨平台成本），只是不對外宣告。README 也不再有介紹開發過程的段落。

第 6 點的其餘部分不變：`docs/decisions/` 整批帶、行為契約與交付流程留在 `AGENTS.md`。

## 補記 2026-10-14：日期放掉，改成清單做完才公開（Sean）

Sean 2026-10-14 表示沒有硬性期限，而這套系統是他最重要的基礎設施。Decision 第 1 點的上線日期不再是期限；公開的條件改為清單完成：

- 進行中的功能 PR 合併。
- 2026-10-13 稽核開出的缺陷票**全部修好**（Sean：都修好之後再公開，影響最小）。
- 獨立的去識別掃描做完、結果經 Sean 看過。

這不是上面最後一條說的反轉：Sean 仍要公開，消失的只有日期。其餘各點不變 —— 展示不等遠端化、全新 repo 不帶舊歷史、公開後主場在公開 repo、兩個收不回來的動作要 Sean 當下授權。

**同日再定：先搬家、後公開，兩步拆開（Sean）。** 搬家＝Sean 的日常使用（信庫、每日同步、全域 `bes` 與 skill、CoWork）改跑新這一版，遠端先用私有的；公開仍是最後一步，照 Decision 第 2 點另建全新的公開 repo、以最終的樹當第一個 commit，私有期間的提交紀錄不帶。Consequences 裡「改名在搬家的同一步做」不變，變的只是搬家不再等公開。缺陷票直接修在這條線上，舊 repo 的 main 不再收程式修正；公開之前 issue 留在舊 repo。「兩個收不回來的動作」原封不動留在最後。

放掉日期之後，Rejected alternatives 裡以時程為理由的兩條（第一版就做到樣本可跑、多人共用）失去了那個理由；兩者沒有因此被採納，要重開需另行決定。
